# Бюджет — личный финансовый планировщик

Показывает, сколько можно потратить сегодня, чтобы хватило на обязательные платежи и сбережения.
Ведёт регулярные доходы и платежи, цели, долги, лимиты по категориям и прогноз остатка с поиском кассового разрыва.
Есть AI-помощник на DeepSeek.

## Быстрый старт

```bash
npm install
npm run dev          # http://localhost:3001
```

Без входа данные хранятся только в браузере. После регистрации они синхронизируются между устройствами.

### Переменные окружения (`.env.local`)

| Переменная | Значение по умолчанию | Зачем |
|---|---|---|
| `DEEPSEEK_API_KEY` | — | ключ для AI-помощника; без него помощник выключен |
| `DATABASE_PATH` | `data/finance.sqlite` | файл базы SQLite |
| `COOKIE_SECURE` | `true` в production | флаг Secure у cookie сессии; ставьте `false`, только если сайт открывается по http не с localhost |
| `ALLOW_REGISTRATION` | `true` | `false` закрывает регистрацию новых пользователей |
| `TRUST_PROXY` | `false` | `true` — сервер за своим прокси (Caddy, nginx): адрес клиента для ограничения частоты берётся из `X-Forwarded-For` |
| `CORS_ORIGINS` | `capacitor://localhost` | откуда разрешены запросы к API с другого источника (iOS-приложение) |

### Перенос данных из старой версии

Перенос с сервера (пользователи и пароли сохраняются, старая база открывается только на чтение):

```bash
npm run import-legacy -- --from ../server/data.sqlite --dry-run   # посмотреть, что перенесётся
npm run import-legacy -- --from ../server/data.sqlite             # перенести
```

Из браузера:
- Если данные лежали только в localStorage старой версии, экспортируйте их там в JSON.
- Затем загрузите файл в «Настройки → Данные → Загрузить из файла».
- Если новая версия открыта на том же адресе, что и старая, она сама предложит перенос.

## Сервер в облаке

Сервер работает на ВМ Ubuntu 24.04: Caddy принимает HTTPS (сертификат Let's Encrypt) и передаёт запросы
приложению на `127.0.0.1:3001`. Адрес и SSH-доступ — в `.env.deploy` (не в git):

```bash
DEPLOY_HOST=budget@<IP>
DEPLOY_URL=https://<IP через дефисы>.sslip.io   # sslip.io даёт имя для сертификата без своего домена
```

Первичная настройка новой ВМ (Node.js, Caddy, служба `budget`, ежедневный бэкап, вход только по ключу):

```bash
rsync -a deploy/ $DEPLOY_HOST:deploy/
ssh $DEPLOY_HOST 'sudo bash deploy/server-setup.sh <IP через дефисы>.sslip.io'
```

Выкладка новой версии — `scripts/deploy.sh`: собирает самодостаточный пакет в `.next-deploy/` (локальный `.next` не трогает),
копирует его на сервер, переключает и перезапускает службу. На сервере хранятся три последние версии.

Где что на сервере:
- база — `/var/lib/budget/finance.sqlite`;
- настройки — `/etc/budget/env` (`DEEPSEEK_API_KEY`, `ALLOW_REGISTRATION=false`, `TRUST_PROXY=true`);
- журнал — `journalctl -u budget`.

Бэкапы:
- служба `budget-backup.timer` каждую ночь кладёт снимок базы в `/var/backups/budget/` и хранит 30 дней;
- LaunchAgent `com.eduard.budget-backup-pull` раз в день копирует их на Mac в `../.backups/server/`.

## iPhone-приложение

Интерфейс собран внутрь приложения (Capacitor), с сервером оно общается по API с токеном.
Без сети изменения копятся на телефоне и отправляются, когда связь появится.

```bash
npm run ios:sync    # адрес сервера — DEPLOY_URL из .env.deploy, иначе этот компьютер в локальной сети (*.local:3001)
```

Сборка и установка на подключённый кабелем iPhone (подпись личным Apple ID — Personal Team):

```bash
cd ios/App && xcodebuild -project App.xcodeproj -scheme App -configuration Debug \
  -destination 'id=<UDID телефона>' -allowProvisioningUpdates build
xcrun devicectl device install app --device <UDID> <путь к App.app из DerivedData>
```

С бесплатной подписью приложение работает 7 дней — затем повторите сборку и установку.

## Как считается лимит на день

Берётся меньшее из двух чисел:

1. **По бюджету месяца**:
   - гибкий бюджет = доходы месяца (с плановыми) − обязательные расходы − цель по сбережениям (15%);
   - из него вычитается уже потраченное до сегодня;
   - остаток делится на оставшиеся дни.
2. **По деньгам на счёте**:
   - остаток минус обязательные платежи до ближайшего дохода;
   - делится на дни до этого дохода.

Если прогноз остатка уходит в минус раньше дохода, приложение предупреждает о кассовом разрыве.

## Устройство

```
src/domain/   чистая логика без зависимостей от React и сервера (суммы — целые копейки, даты — строки YYYY-MM-DD)
  schema.ts       схема данных (zod)
  actions.ts      все изменения данных — действия; applyAction(state, action) → state
  recurring.ts    регулярные платежи: одно начисление на шаблон в месяц, без дублей и задним числом
  metrics.ts      баланс, бюджет месяца, лимит на день, прогноз и кассовый разрыв, аналитика
  savings.ts      автоотчисления в сбережения (с зарплаты и «копилка» с покупок)
  migrate.ts      перенос данных из старых версий
  ai.ts           снимок данных для модели и разбор её предложений
src/server/   SQLite (node:sqlite), сессии, ограничение частоты запросов, применение действий
src/client/   хранилище на клиенте: оптимистичные изменения, очередь отправки, офлайн, гостевой режим
src/components/  интерфейс
src/app/api/  HTTP API
```

Синхронизация устроена так:
- Клиент отправляет на сервер не всё состояние, а действия.
- Сервер применяет их тем же кодом (`applyAction`) атомарно в транзакции и проверяет результат схемой.
- Если данные менялись с другого устройства, клиент подтягивает свежую версию и накладывает свои неотправленные действия сверху. Поэтому две вкладки или два телефона не затирают друг друга.

Безопасность:
- Сессия — случайный токен; в базе хранится его SHA-256. Cookie `HttpOnly`, `SameSite=Lax`, `Secure` в production.
- Изменяющие запросы с чужих сайтов отклоняются.
- Вход, регистрация и AI ограничены по частоте.
- AI доступен только после входа. Модели уходит снимок данных пользователя, собранный на сервере, а её предложения применяются только после подтверждения.

## Команды

```bash
npm run dev         # разработка
npm run build       # production-сборка
npm start           # запуск собранной версии (порт 3001)
npm test            # тесты (vitest)
npm run check       # типы + линтер + тесты
```

Запускайте один экземпляр сервера: база SQLite и счётчики ограничения частоты живут в одном процессе.
Для доступа из интернета нужен HTTPS — см. «Сервер в облаке».
